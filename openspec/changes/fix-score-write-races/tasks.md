Deliberately omitted: tests that fire genuinely concurrent submissions and assert on a winner.
Their outcome turns on connection timing, so they would pass without proving anything and fail
without a bug. Row locking is Postgres behaviour rather than ours; the conditional upsert is
what this change relies on, and 8.1 covers it.

Note for whoever next runs the browser-driven tests against a non-default backend port:
`proxyFrontendAPIToBackend`'s `page.route()` interception only redirects HTTP requests. The
Socket.IO connection a browser page opens goes straight to `NEXT_PUBLIC_API_URL_DEV`
(`localhost:8001` in `.env.development`), unproxied — run the backend on that port, or the
page's live updates (score broadcasts, run-status locks) silently never arrive while its
initial REST-loaded state still looks fine.
