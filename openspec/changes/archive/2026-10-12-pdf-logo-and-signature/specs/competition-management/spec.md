# Spec Delta

## ADDED Requirements

### Requirement: Operators can upload a competition logo and head judge signature
The webapp SHALL let an operator, on the Admin page, upload a logo image and a head judge
signature image for the selected competition, see a preview of each stored image, and delete
either one. Both images SHALL be optional and independent of each other. The server SHALL
accept only PNG or JPEG images of at most 10 MB each, and SHALL replace any image of the same
kind already stored for that competition when a new one is uploaded.

#### Scenario: Uploading a logo stores it for the competition
- **WHEN** an operator uploads a PNG logo for a competition that has none
- **THEN** the server stores it, and requesting that competition's logo returns the same image

#### Scenario: Uploading again replaces the stored image
- **GIVEN** a competition already has a stored signature
- **WHEN** an operator uploads a different signature image
- **THEN** requesting the competition's signature returns the new image, not the old one

#### Scenario: Deleting an image removes it
- **GIVEN** a competition has a stored logo
- **WHEN** an operator deletes the logo
- **THEN** requesting the competition's logo returns `404 Not Found`, and the competition's
  signature, if any, is unaffected

#### Scenario: A file that is not a PNG or JPEG image is rejected
- **WHEN** an operator uploads a file whose contents are not a PNG or JPEG image, whatever
  its file name or declared content type
- **THEN** the server answers `415 Unsupported Media Type`, stores nothing, and keeps any
  image already stored

#### Scenario: An image larger than 10 MB is rejected
- **WHEN** an operator uploads an image larger than 10 MB
- **THEN** the server answers `413 Content Too Large`, stores nothing, and keeps any image
  already stored

#### Scenario: Uploading for a competition that does not exist
- **WHEN** an image is uploaded for a competition id that does not exist
- **THEN** the server answers `404 Not Found` and stores nothing

## MODIFIED Requirements

### Requirement: Operators can download a PDF of a phase's results
The webapp SHALL let an operator download a PDF, generated by the server, listing every athlete in the selected phase with their rank, per-run scores, total score, and tie-break reason. When the phase's competition has a stored logo, every page SHALL show it at the top right of the title row, with the title kept clear of it. The webapp SHALL offer a "Signed by head judge" switch next to the download, off by default and always enabled. When the switch is on, the PDF SHALL end with a signature block after the results table: the competition's stored head judge signature image, or a blank line to sign by hand when none is stored, above the label "Head Judge" and the date the PDF was generated. When the switch is off, the PDF SHALL contain no signature block.

#### Scenario: Downloading a phase results PDF
- **WHEN** an operator selects a phase and requests its results PDF
- **THEN** the server returns a PDF containing the rank, run scores, total score, and reason for every athlete in the phase

#### Scenario: A competition logo appears on every page of the phase results PDF
- **GIVEN** the phase's competition has a stored logo
- **WHEN** an operator requests a phase results PDF that runs to more than one page
- **THEN** every page shows the logo at the top right of the title row

#### Scenario: A phase results PDF without a logo
- **GIVEN** the phase's competition has no stored logo
- **WHEN** an operator requests its results PDF
- **THEN** the PDF contains no logo image

#### Scenario: Signed with a stored signature
- **GIVEN** the phase's competition has a stored head judge signature
- **WHEN** an operator turns on "Signed by head judge" and requests the phase results PDF
- **THEN** the PDF ends with the signature image above the label "Head Judge" and the date

#### Scenario: Signed without a stored signature
- **GIVEN** the phase's competition has no stored head judge signature
- **WHEN** an operator turns on "Signed by head judge" and requests the phase results PDF
- **THEN** the PDF ends with a blank signature line above the label "Head Judge" and the date

#### Scenario: Unsigned results have no signature block
- **GIVEN** the phase's competition has a stored head judge signature
- **WHEN** an operator requests the phase results PDF with "Signed by head judge" off
- **THEN** the PDF contains neither the signature image nor the "Head Judge" label

#### Scenario: Signing does not depend on runs being confirmed
- **GIVEN** a phase with runs the head judge has not yet confirmed
- **WHEN** an operator turns on "Signed by head judge" and requests the phase results PDF
- **THEN** the PDF includes the signature block

### Requirement: Operators can download a PDF heat draw for one or more heats
The webapp SHALL let an operator select one or more heats and download a PDF listing each selected heat's competitors (name, event, bib, affiliation, and prior-phase rank). When a heat's competition has a stored logo, that heat's page SHALL show it at the top right of the title row, with the title kept clear of it.

#### Scenario: Downloading a draw for multiple heats
- **WHEN** an operator selects several heats and requests a heat summary PDF
- **THEN** the server returns a single PDF with one page per selected heat, and names the file after the number of heats included

#### Scenario: A competition logo appears on each heat draw page
- **GIVEN** the heats' competition has a stored logo
- **WHEN** an operator requests a heat summary PDF for several heats
- **THEN** every page shows the logo at the top right of the title row

### Requirement: Operators can download a PDF of a single heat's run-by-run results
The webapp SHALL let an operator download a PDF of a single heat's athletes with their score for each run. When the heat's competition has a stored logo, every page SHALL show it at the top right of the title row, with the title kept clear of it.

#### Scenario: Downloading a heat's results PDF
- **WHEN** an operator selects a heat and requests its results PDF
- **THEN** the server returns a PDF containing every athlete's per-run scores for that heat

#### Scenario: A competition logo appears on the heat results PDF
- **GIVEN** the heat's competition has a stored logo
- **WHEN** an operator requests the heat's results PDF
- **THEN** the PDF shows the logo at the top right of the title row
